# Security and sensitive evidence

Do not include secrets, access tokens, account information, customer data or unredacted private evidence in public issues or Git history. Report ordinary metadata corrections through the correction issue template.

For a vulnerability or accidental exposure, use GitHub's private vulnerability reporting when enabled or the organization's established private maintainer channel. If neither is available, contact an organization owner through an existing trusted private channel before sharing sensitive details. This scaffold does not claim private reporting is enabled.

Researching a product is not authorization to test production systems, bypass access controls or run offensive evaluations. Record permitted test conditions and use synthetic accounts/data only when independently authorized.
